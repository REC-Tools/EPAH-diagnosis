# EPAH Diagnosis v0.2.0-rc1 — Technical Software Pre-release

**This is a PUBLIC pre-release of the software source code only. It is NOT a validated or institutionally approved energy-poverty diagnosis.**

**Italiano:** rilascio preliminare del *software*, non pubblicazione del rapporto, delle mappe, dei dati o dei risultati come diagnosi ufficiale della Green Community / EPAH / Commissione europea.

## Funzionalità software della v0.2

- Profilazione territoriale dei **27 Comuni** della Green Community Sinergie in Canavese basata sul bundle tecnico pilota v0.1 già verificato.
- Generazione del rapporto territoriale tecnico in PDF, con tabelle e mappe del pilota (#122).
- Generazione di **27 schede comunali A4** con anni delle fonti e otto indicatori numerici più classificazione SNAI (#123).
- Confronto **multidimensionale descrittivo**, 28 coppie tra otto indicatori numerici, senza indice composito o graduatoria di rischio (#124).
- Dashboard **offline** con filtri e confronti comunali, senza servizi esterni e senza dati personali (#125).
- Pacchetto tecnico per revisione, con checklist di approvazione ancora in sospeso (#126).
- Controlli più forti di coerenza tra dati, dashboard, report e ZIP, con audit read-only (#128).
- Ambiente riproducibile con `uv.lock` e Python 3.11+.

## Ambito e limiti

**Questa pre-release non include né pubblica dati, mappe, PDF, archivio delle 27 schede o ZIP tecnico come asset GitHub.** Gli unici asset sono l'archivio sorgente generato da GitHub e il JSON di provenienza del commit. Gli artefatti tecnici devono essere generati localmente da un bundle pilota già verificato e restano sotto review.

Non rappresenta una diagnosi approvata dall'Unione Montana, da EPAH o dalla Commissione europea. Non misura la povertà energetica delle singole famiglie, non stima consumi o spese delle abitazioni, non genera un indice composito e **non include i dati CIT ancora in quarantena**. La verifica automatica di hash e struttura non equivale a validazione scientifica.

Le condizioni per una futura release istituzionale rimangono: controlli delle fonti/licenze, revisione dei nove metodi e dei confronti multi-anno, verifica visiva di tutti i PDF, review editoriale del branding, parere/approvazione istituzionale e autorizzazione esplicita alla diffusione. Il gate canonico v0.1 delle 243 osservazioni e delle approvazioni non viene aggirato.

## Esecuzione (Windows / PowerShell)

Da una copia aggiornata di questa versione del codice:

```powershell
uv sync --python 3.11 --locked --group dev
uv run --locked pytest -q
uv run --locked epah status
```

Con il bundle tecnico pilota v0.1 già disponibile e verificato in `outputs/v0.1.0-pilot`, creare **sempre cartelle nuove**:

```powershell
uv run --locked epah report v0.2
uv run --locked epah sheets v0.2
uv run --locked epah analysis v0.2
uv run --locked epah dashboard v0.2
uv run --locked epah review-pack v0.2
uv run --locked epah audit v0.2
```

I comandi finali non vanno usati se mancano gli input o le evidenze QA del pilota; la CI della pre-release testa il software con **dati sintetici**, non distribuisce il rapporto reale e non attesta l'avvenuta approvazione.
