# EPAH Diagnosis v0.2.0 — Stable software toolkit (source only)

**Stable software release; not a validated or institutionally approved diagnosis.**

La versione `v0.2.0` del **software** consente di eseguire localmente una diagnosi territoriale tecnica dei 27 Comuni della Green Community Sinergie in Canavese. La release **non** autorizza la pubblicazione dei risultati, l'uso istituzionale del rapporto o l'attribuzione di povertà energetica alle singole famiglie.

## Funzionalità incluse

- Compilazione di rapporto tecnico in PDF e 27 schede comunali A4 a partire da un bundle pilota v0.1 controllato.
- Tabelle descrittive con otto indicatori numerici e classificazione SNAI, anni e mediane comunali distinti.
- Confronto trasparente delle 28 coppie di dimensioni, senza punteggio composito né ranking di vulnerabilità.
- Dashboard HTML offline con ricerca per Comune, filtro SNAI e confronto tra indicatori.
- Pacchetto ZIP di **review tecnica** e audit read-only di file, SHA-256 e corrispondenza dei dati.
- **PR #131:** segnalazione automatica delle serie perfettamente coincidenti (nel collaudo precedente, tempi stradali verso scuole secondarie e ferrovia coincidenti in 27/27 Comuni).
- Test automatici, riproducibilità con `uv.lock` e vincoli contro la modifica dei dataset originali.

## Cosa è stabile e cosa rimane da approvare

**Stabile:** interfacce CLI e contratti dei formati di output, controlli di riproducibilità e di integrità, metodologia descrittiva implementata.

**Non approvato:** la diagnosi istituzionale, i nove indicatori come misure scientificamente validate di povertà energetica, le licenze/fonte a livello di pubblicazione, le interpretazioni causali e l'autorizzazione a distribuire mappe, schede e PDF ufficiali. Il gate canonico di promozione della v0.1 resta distinto e non è aggirato.

Lo screening non misura consumi energetici o spesa energetica individuale, non individua nuclei familiari vulnerabili e non produce un indice composito. **I dati CIT in quarantena sono esclusi.** La coincidenza numerica di indicatori non dimostra che siano metodologicamente equivalenti: verificare le relative fonti e destinazioni.

## Installazione e riproducibilità

Da un clone pulito della repository e una versione Python 3.11+, in un terminale Windows CMD:

```bat
git fetch origin --tags
git checkout v0.2.0
uv sync --python 3.11 --locked --group dev
uv run --locked pytest -q
uv run --locked epah status
```

Se gli input e il bundle pilota v0.1 verificato sono disponibili localmente, generare i file in **cartelle nuove**:

```bat
set "BUNDLE=outputs\v0.1.0-pilot"
set "RUN=outputs\v0.2-technical-%RANDOM%"
uv run --locked epah report v0.2 --bundle "%BUNDLE%" --out-dir "%RUN%\report"
uv run --locked epah sheets v0.2 --bundle "%BUNDLE%" --out-dir "%RUN%\sheets"
uv run --locked epah analysis v0.2 --bundle "%BUNDLE%" --out-dir "%RUN%\analysis"
uv run --locked epah dashboard v0.2 --bundle "%BUNDLE%" --analysis-dir "%RUN%\analysis" --out-dir "%RUN%\dashboard"
uv run --locked epah review-pack v0.2 --bundle "%BUNDLE%" --report-dir "%RUN%\report" --sheets-dir "%RUN%\sheets" --analysis-dir "%RUN%\analysis" --dashboard-dir "%RUN%\dashboard" --out-dir "%RUN%\review"
uv run --locked epah audit v0.2 --dir "%RUN%\review"
```

Interrompere la sequenza se un comando fallisce. I test CI sono eseguiti su fixture sintetiche; la review su output territoriali reali richiede un bundle disponibile localmente.

## Contenuto GitHub Release

La **release del software** allega esclusivamente i sorgenti GitHub e `source_only_v0.2.0_attestation.json` (identità, SHA commit, scope tecnico/non istituzionale). Non allegare ZIP, mappe, PDF, CSV territoriali o fonti grezze generati localmente.

La pubblicazione del tag **non è automatica al merge** della PR: il responsabile deve prima completare il collaudo sui nuovi output e poi lanciare manualmente il workflow `Publish v0.2.0 stable software-only release` su `main`. Il workflow ripete la CI tecnica e verifica il tag/attestazione pubblicati senza sovrascrivere release precedenti.

Ulteriori informazioni: `docs/v0_2_review_package.md` e `docs/v0_2_identical_indicators_review.md`.
