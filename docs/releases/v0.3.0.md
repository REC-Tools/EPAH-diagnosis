# EPAH Diagnosis v0.3.0 — Stable software toolkit (source only)

**SOFTWARE STABILE - NON È UNA DIAGNOSI SCIENTIFICAMENTE O ISTITUZIONALMENTE APPROVATA.**

La versione `v0.3.0` del **software** aggiunge alla v0.2.0 gli strumenti per acquisire, normalizzare, verificare e visualizzare i **nuovi indicatori candidati** ispirati all'EPAH Handbook per i 27 Comuni della Green Community Sinergie in Canavese. La release **non** autorizza la pubblicazione dei risultati, non promuove alcun candidato nel catalogo canonico e non attribuisce povertà energetica alle singole famiglie.

## Funzionalità incluse

- **Tutto il toolkit v0.2.0, invariato:** rapporto PDF, 27 schede comunali, analisi multidimensionale, dashboard offline, review-pack e audit (`epah ... v0.2`).
- **Registro scientifico EPAH v0.3:** 56 indicatori, 35 fonti, 12 priorità e crosswalk con i nove indicatori canonici, controllati da `scripts/check_v0_3_evidence.py`.
- **Pipeline dei candidati** (ID interni all'inventario, non ID ufficiali EPAH):

| ID | Candidato | Strumenti | Stato dei dati al rilascio |
| --- | --- | --- | --- |
| H47 | Residenti 0–11 anni (ISTAT POSAS 2026) | intake, QA, riproduzione indipendente | anteprima reale 27/27, riprodotta in modo indipendente |
| H50 | Adulti 25–64 senza licenza media (Censimento 2024) | normalizzazione SDMX, builder, audit indipendente | anteprima reale 27/27, audit PASS |
| H46 | Disoccupazione 15+ (Censimento 2024) | acquisizione SDMX, normalizzazione, builder, audit indipendente | anteprima reale 27/27, audit PASS |
| H03 | HDD climatici annui 2025 (ARPA NWIOI) | estrazione NetCDF, calcolo Eurostat | solo pipeline: NetCDF non acquisiti |
| H04 | CDD annui 2025 (ARPA NWIOI) | calcolo Eurostat sugli stessi dati H03 | solo pipeline |
| H05 | APE residenziali F/G | intake e QA | solo pipeline: fonte non acquisita |
| ADD-HOUSING-01 | Abitazioni non occupate da residenti (ISTAT 2023) | intake e QA | solo pipeline: fonte non acquisita |

- **Atlante esplorativo v0.3** (`scripts/build_v0_3_visual_atlas.py`): HTML offline con mappe nuove in EPSG:32632 e grafici di distribuzione. Ha 13 posizioni: 9 indicatori del pilota più H47, H50, H46, H03. Mostra `DATI ASSENTI` per le serie non fornite e non inventa valori.
- Ogni anteprima e audit ha manifest SHA-256 e stato `technical_draft_do_not_publish`; le cartelle di output non vengono mai sovrascritte.

## Cosa è stabile e cosa rimane da approvare

**Stabile:** interfacce e contratti dei formati di input/output delle pipeline v0.3, controlli fail-closed, riproducibilità con `uv.lock`, atlante offline.

**Non approvato:** le mappature dai codici ISTAT ai gruppi dei candidati (verificate solo tecnicamente sulle etichette dei metadati), le definizioni dei candidati come misure di vulnerabilità, la comparabilità fra anni e universi diversi, la diffusione di mappe o valori. **Nessun candidato è entrato in `config/indicators.json` o in `data/verification_matrix.csv`**: il catalogo canonico resta di nove indicatori.

Limiti noti da considerare nella revisione:

- H46 ha denominatori molto piccoli in 4 Comuni (Ingria ~13, Ribordone ~15, Valprato Soana ~43, Noasca ~43 persone nelle forze di lavoro), segnalati in `qa.json`.
- L'atlante non ha ancora posizioni per H04, H05 e ADD-HOUSING-01.
- Le serie stradali verso scuola superiore e ferrovia del pilota coincidono in 27/27 Comuni.
- **I dati CIT in quarantena restano esclusi.**

Nessun prodotto stima consumi o spesa energetica delle famiglie, né produce un indice composito o una graduatoria di povertà energetica.

## Installazione e riproducibilità

Da un clone pulito, con Python 3.11+ e [uv](https://docs.astral.sh/uv/), in PowerShell:

```powershell
git fetch origin --tags
git checkout v0.3.0
uv sync --python 3.11 --locked --group dev
uv run --locked pytest -q
uv run --locked epah status
uv run --locked python scripts/check_v0_3_evidence.py
uv run --locked python scripts/check_v0_3_release.py
```

Con il bundle pilota v0.1 verificato e le anteprime dei candidati disponibili localmente, l'atlante si genera in una **cartella nuova**:

```powershell
$run = "outputs/v0.3-atlas-$(Get-Date -Format yyyyMMdd-HHmmss)"
uv run --locked python scripts/build_v0_3_visual_atlas.py --bundle outputs/v0.1.0-pilot --out-dir $run
```

Le procedure per ottenere le anteprime reali sono in [v0_3_h46_official_normalization_and_independent_audit.md](../v0_3_h46_official_normalization_and_independent_audit.md), [v0_3_h50_education_candidate.md](../v0_3_h50_education_candidate.md), [v0_3_h47_source_reproduction_audit.md](../v0_3_h47_source_reproduction_audit.md) e [v0_3_visual_atlas.md](../v0_3_visual_atlas.md). I test CI usano solo fixture sintetiche; le verifiche sui dati reali dei 27 Comuni richiedono gli originali conservati localmente.

## Contenuto GitHub Release

La **release del software** allega esclusivamente i sorgenti GitHub e `source_only_v0.3.0_attestation.json` (identità, SHA commit, scope tecnico/non istituzionale, stato dei candidati). Non allegare atlanti, anteprime CSV, mappe, PDF, export ISTAT/ARPA o altri file generati localmente.

La pubblicazione del tag **non è automatica al merge**: il responsabile, dopo aver verificato l'atlante sui dati locali, lancia manualmente il workflow `Publish v0.3.0 stable software-only release` su `main`. Il workflow ripete la CI tecnica e verifica tag e attestazione, senza sovrascrivere release esistenti. La release `v0.2.0` resta disponibile e invariata.
