# EPAH Diagnosis v0.4.0 — Stable Software (Source Only)

Release software per preparare, consultare e revisionare prodotti dei **27 Comuni**
di Sinergie in Canavese. I risultati territoriali rimangono
`technical_draft_do_not_publish`: approvazione scientifica e istituzionale **pending**.

## Funzioni disponibili

- Percorso unico `epah outputs plan/run`, file dichiarativo degli input, destinazioni
  nuove, ricevute, manifest e gestione esplicita dei pacchetti incompleti.
- Portale locale, atlante, PDF e schede con inventario delle serie e modello CSV
  di revisione; builder riutilizzabili in libreria e wrapper storici compatibili.
- Esempio sintetico senza originali privati, renderer e audit condivisi.
- Controlli Bash riproducibili su Windows e documentazione per nuovi contributori.
- Validazione di 18 contratti metodologici proposti per v0.5: nessuna nuova serie
  municipale, formula approvata o promozione nel catalogo canonico.

## Installazione e prima prova

Con Git, Python 3.11 e uv installati:

```powershell
git clone --branch v0.4.0 https://github.com/REC-Tools/EPAH-diagnosis.git
cd EPAH-diagnosis
uv sync --python 3.11 --locked --group dev
uv run --locked epah --version
uv run --locked python scripts/check_documentation.py
uv run --locked epah examples synthetic --out-dir work/synthetic-v040-01
```

Aprire `work/synthetic-v040-01/hub/index.html`. Usare una destinazione nuova
per ogni esecuzione. Per i test e il Bash richiesto su Windows vedere la
[guida sviluppatore](../v0_4_developer_guide.md). Per gli input reali seguire la
[chiusura tecnica parziale](../v0_4_technical_closeout.md).

## Limiti scientifici e contenuto pubblico

Il catalogo canonico conserva nove indicatori/descrittori. Lo snapshot tecnico
locale contiene 13 delle 16 serie previste; non è incluso nella release.
H03/H04 hanno originali disponibili ma decisioni metodologiche aperte; H05
richiede una fonte APE residenziale comunale. La mappatura delle abitazioni e
le altre anteprime richiedono ancora revisione umana. CIT in quarantena escluso.
Non si produce una prevalenza familiare o un punteggio composito di povertà energetica.

GitHub distribuisce i sorgenti e il solo asset aggiuntivo
`source_only_v0.4.0_attestation.json`. Non vengono allegati pacchetti territoriali,
PDF, originali, configurazioni locali o log privati. L'attestazione identifica
commit, lockfile e contratto di release; non certifica i risultati territoriali.

## Procedura di rilascio e sviluppo successivo

La release segue una PR revisionabile con controlli CI. Il workflow manuale
`v04-stable-software.yml` accetta solo `main` e richiede `expected_sha` uguale
al commit selezionato; ripete suite bloccata, documentazione e gate, verifica
tag e asset e non sostituisce una release esistente. Le release precedenti
rimangono disponibili, senza modificare i loro contratti storici.

Il lavoro v0.5 prosegue su branch dedicati con PR distinte, secondo
[CONTRIBUTING](../../CONTRIBUTING.md). Le decisioni scientifiche restano separate
dai controlli software e dalle interviste di validazione territoriale.
